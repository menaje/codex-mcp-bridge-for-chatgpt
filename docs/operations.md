# 운영과 진단 보존 정책

메뉴바와 helper 상태 조회는 프로세스 실행 여부, Bridge의 신규 작업 접수 여부, Tunnel 준비 상태를 구분한다. helper는 비정상 종료 시 제한된 backoff로 재시도하고, 5분 안에 3회를 넘는 반복 종료는 safe mode로 남겨 사용자가 복구하도록 한다. 정상 중지와 재시작은 admission을 닫고 진행 중 작업 및 백그라운드 프로세스의 영향을 확인한다.

## 로그

macOS helper의 진단 로그는 메모리에만 저장한다. 기본 상한은 **200건, UTF-8 JSON 기준 1MiB, 24시간**이며 먼저 도달한 제한에 따라 오래된 항목을 제거한다. 쓰기뿐 아니라 읽기 때에도 만료를 검사하므로 유휴 상태에서 옛 로그가 계속 반환되지 않는다. helper 재시작 시 로그는 사라진다. 기본 LaunchAgent의 stdout/stderr는 `/dev/null`로 보내며 브리지 자체가 원본 프로세스 로그를 디스크에 무제한 저장하지 않는다.

직접 helper를 실행하는 운영 환경에서는 `--log-retention-hours`(1–168시간), `--log-max-kib`(16–4096KiB)로 제한을 설정할 수 있다. 메뉴바 앱의 기본 실행은 위 기본값을 사용한다. 외부 서비스 관리자가 stdout/stderr를 별도 파일에 저장하도록 바꾼 경우 그 파일의 순환과 삭제는 해당 관리자의 정책이다.

64KiB를 넘는 개별 런타임 출력 줄은 생략한다. 인증키·토큰·설정 비밀은 기존 공통 redaction을 거친 후에만 보관한다. 로그의 보존 정책은 Codex 대화 기록, 프로젝트, Codex 설치본, 작업 결과 보존과 별개다.

## 장기 작업과 유휴 기록

정상 실행 중인 Codex 작업에는 임의 시간 제한을 두지 않는다. HTTP 연결 종료, 앱 닫기, 관찰 대기 시간 초과와 실제 작업 취소를 구분한다. 취소에는 정확한 Job과 기록되는 취소 의도가 필요하며, 안전한 런타임 종료는 진행 중 작업·승인·입력·백그라운드 프로세스를 먼저 확인한다.

유휴 Agent와 지속 저장된 스레드는 시간이 지났다는 이유만으로 삭제하거나 이어가기를 차단하지 않는다. 오래된 작업의 결과 본문은 기본 6시간/100건의 보존 창을 따르고 결과를 제외한 제한된 요약을 남긴다. 기록 정리는 실행 중 작업을 강제 종료하지 않는다. 메모리 전용 스레드와 사용 중 설치본은 런타임 정리에서 보호한다. 상세 저장 범위는 [보안 문서](security.md)와 [Codex 실행 환경](codex-runtimes.md)을 따른다.

지속 저장된 대화의 연결은 마지막 실제 작업 종료가 저장된 뒤 유휴 6시간이 지나면 안전한 해제를 시도한다. `CODEX_MCP_BRIDGE_THREAD_IDLE_MS`는 결과 보관 TTL과 별도이며, `0`으로 자동 해제를 끌 수 있다. 조회와 알림은 이 시각을 연장하지 않는다. 앱 인계는 이 유예를 기다리지 않고 시작하지만 진행 중 작업·미해결 입력·백그라운드·공유 프로세스를 보호한다. 구독 해제 응답만으로 완료 처리하지 않으며 실제 unload 또는 프로세스 종료를 확인한 뒤 앱을 연다.

현행 schema 19 업그레이드는 최초 지원 스키마의 일관된 비공개 사본 하나를 만든 뒤, schema 14에서 도입한 이벤트 정리를 500개씩 재개 가능하게 처리한다. 반복 진행 기록은 최신 상태로 합치고 작업당 256건, 본문당 8KiB, 전체 Job 이벤트 5만 건·본문 64MiB 상한과 진단 메타데이터 7일 보존을 적용한다. 결과 만료 뒤에는 원문 이벤트를 남기지 않지만 정식 종료 상태, 사용량·실행 선택 요약과 전달·취소·중복 방지 근거는 보존한다. 미전달 결과와 미해결 응답, 취소, 유효한 보존 지정은 일반 결과 정리보다 우선한다.

현행 schema 19에는 schema 17의 후속 작업 표시 기록·선택적 확인·자동 복구 사건, schema 18의 기존 보관 Agent 복원, 프로젝트·실행 문맥·Job·이벤트·요약 정규화가 포함된다. 표시 기록은 기본 30일이며 설정에서 7·30·90일·무기한을 선택한다. 결과 본문과 진단 이벤트의 보존 한도는 별도로 유지한다. 종료된 실패를 현재 처리 필요 항목에 섞지 않고, 최소 중복 실행 방지 근거는 표시 기록 만료 후에도 보존한다. 사건별 최대 3회의 자동 복구 한도는 재시작 후에도 유지하며, GPT의 복구 판단은 원래의 열린 foreground 호출 안에서만 반환한다. [작업 기록과 복구 계약](work-history.md)을 참고한다.

schema 18부터 브리지는 Agent를 기간 기준으로 보관하지 않으며 `codex_agent`는 이름 변경만 제공한다. 유휴 연결 해제, 실행 기록·결과 본문 정리, 프로젝트 보관·복원과 Codex 원본 대화 수명은 각각 별도 정책으로 유지한다. 정리 후 DB 파일 크기가 즉시 줄지 않아도 빈 페이지는 재사용되며, 파일 축소는 안전하게 중지한 뒤 별도 오프라인 작업으로 수행한다. 전체 schema 19 소유권·보존·백업·압축 절차는 [DB schema와 수명](database-schema.md), 연결 및 캐시 측정 범위는 [연결 및 DB 보존 정책](thread-lifecycle.md)에 정리했다.

## 브리지 알림

브리지/helper/Tunnel/설정/인증 문제와 원격 보안 확인에만 시스템 알림을 사용한다. 60초의 유예 기간을 넘긴 문제는 원인별로 한 번 알리고, 미해결 기록을 앱 설정에 저장해 앱 재시작에 따른 중복을 막는다. 잠깐 정상 응답한 뒤 다시 끊기는 상황도 60초의 안정적인 복구를 확인하기 전에는 새 알림으로 반복하지 않는다.

복구 시간은 실제로 연속해서 관찰한 구간만 계산한다. 앱 재시작 또는 상태 확인 공백이 있으면 복구 시간 계산을 새로 시작하고, 이미 알린 미해결 원인은 계속 보존한다.

Codex 작업 완료·실패·질문·승인과 정상 복구는 브리지 알림 대상이 아니다. 연결 설정에서 두 알림 종류를 켜거나 끌 수 있고 macOS의 알림 권한 및 집중 모드를 따른다. 알림 권한이 없어도 메뉴바의 상태와 복구 버튼은 유지된다. 알림 본문은 고정된 비민감 안내만 사용하며 클릭하면 관련 연결 또는 Codex 설정으로 이동한다.

## 반복 검증

- `npx tsx scripts/card-state-restart-audit.ts /absolute/state.sqlite report.json`: 읽기 전용 일관 백업에서 schema 19 이관과 두 번의 재시작을 수행하고 유지 대상·허용된 구 문맥 폐기·현재 카드 읽기를 의미 단위로 비교한다.
- `npx tsx scripts/database-storage-audit.ts /absolute/state.sqlite report.json`: 원본은 읽기 전용으로 계측하고 임시 사본에서 쿼리 계획·지연·직렬화·쓰기 경로·DB/WAL/백업/빈 페이지와 오프라인 `VACUUM INTO` 복구 절차를 검증한다.
- `npm run test:continuity`: 격리된 MCP/작업/실행 프로세스 계층의 연속성을 세 단계로 확인하고 실패 단계를 출력한다.
- `npm run macos:remote:check`: 임시 HTTPS 서버와 실제 Swift 클라이언트 사이의 페어링, 상태 조회, 잘못된 인증 및 인증서 거부를 확인한다.
- `npm run macos:check`: 운영 알림 정책, 권한 거부, 반복 알림 방지, 재시작, 상태·접근성 라벨, native 계약과 번역을 검증한다.
- `npm run test:launchd-lifecycle`: macOS의 전용 임시 LaunchAgent로 61초 예약, helper 비정상 종료·재기동, 빌드 교체와 종료/모드 전환 인계 기록을 검증한다. 먼저 `npm run build`로 검증할 helper를 빌드한다. 작업·터널 응답과 네이티브 호출자의 완료 기록은 합성이며 실제 앱 화면/기기 복구 검증은 별도다.

이 검사들은 설치된 앱이나 실제 작업을 교체·중단하지 않으며 모델 과금을 발생시키지 않는다. 물리적인 sleep/wake·서로 다른 Mac·실제 ChatGPT surface 검증과 배포는 별도 기록한다.
