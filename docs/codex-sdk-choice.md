# Python SDK 선택 근거

2026-09-06에 [OpenAI Codex SDK 공식 문서](https://learn.chatgpt.com/docs/codex-sdk)를 확인하고 현재 브리지의 계약 테스트와 비교했다.

| 항목 | Python | TypeScript |
| --- | --- | --- |
| 공식 패키지 | `openai-codex` | `@openai/codex-sdk` |
| 공식 문서의 실행 환경 | Python 3.10 이상 | Node.js 18 이상 |
| 주요 사용 방식 | 로컬 app-server와 JSON-RPC로 통신하며 고정된 Codex CLI 런타임을 포함 | 스레드를 시작하고 `run`으로 실행·연속 대화하며 ID로 재개 |
| 이 저장소에서의 상태 | 공개 클라이언트·응답 모델·알림·승인 콜백을 실제 설치된 SDK로 검증 | 별도 백엔드로 구현하거나 동등한 계약 테스트를 수행하지 않음 |

Python SDK를 선택한 이유는 브리지가 필요로 하는 인증, 스레드 식별자, 스트리밍, 승인·입력 콜백, 취소를 현재 어댑터의 app-server 계약으로 검증할 수 있었기 때문이다. 이것은 이 구현에 대한 판단이며 TypeScript SDK가 해당 기능을 제공할 수 없다는 뜻은 아니다. 두 SDK를 동시에 관리하는 추가 설치·인증·지원 범위는 만들지 않는다.

SDK는 CLI의 다른 이름이 아니라 브리지가 따로 관리하는 실행 경로다. SDK 내부 CLI는 해당 SDK 번들과 함께 검증하며, 앱/터미널 CLI의 사용자 선택을 바꾸지 않는다. 기존 Agent는 자신이 생성된 백엔드와 인증 모드에 계속 연결되고, 기본 백엔드 변경은 새 Agent에 적용된다. 세션 표시 설정은 저장 프로필을 선택하며 Codex 앱의 실시간 목록 갱신까지 보장하지 않는다.

설치에는 설치 시점의 최신 안정 버전을 조회하고, 실제 선택한 SDK·Python·내부 CLI 버전과 해시를 기록한다. 복구는 기록된 버전을 사용한다. API 인증은 명시적으로 선택하고 비용 사용을 확인한 경우에만 허용하며 ChatGPT 인증 실패를 API 인증으로 자동 대체하지 않는다.

검증은 `npm run sdk:check`로 수행한다. `CODEX_MCP_BRIDGE_SDK_TEST_PYTHON`에 격리된 SDK Python을 지정하면 실제 SDK와 가짜 app-server 사이에서 인증 거부, 연속 대화·재개·분기, 승인·입력, 조향·취소를 확인한다. `CODEX_MCP_BRIDGE_SDK_LONG_TEST=1`은 10분을 넘는 실행을 추가한다. 이 경로는 모델 요청이나 API 비용을 발생시키지 않는다. 설치 시 실행되는 오프라인 검사와 전체 계약 검사의 범위 차이는 #29의 남은 설치 승인 게이트 작업으로 추적한다.

## 확인된 제한: 만료된 입력

2026-09-06에 SDK 0.147.0으로 만료 입력을 시험했을 때 완료를 받지 못했고 15초 재현 검사에서 실패했다. 설치된 SDK의 `CodexClient`는 단일 수신 스레드에서 공개 `approval_handler`를 동기 호출한다. 브리지는 서버 소유의 만료 요청에 늦은 응답을 보내지 않는데, SDK 콜백은 응답을 기다려 뒤의 완료 이벤트를 읽지 못한다. 정상 승인/입력과 610초 일반 실행 통과를 이 만료 경로의 통과로 확대하지 않는다.

`CODEX_MCP_BRIDGE_SDK_EXPIRY_REPRO=1 npm run sdk:check`로 기대 동작을 재현할 수 있다. 이 검사는 현재 실패하므로 일반 검사에서는 명시적으로 제외한다. 실제 모델 호출은 없다. SDK의 비공개 수신부를 수정하거나 직접 CLI로 우회하지 않았다. #29는 이 제한과 설치별 전체 계약 승인 게이트를 해결하기 전까지 완료하지 않는다.
