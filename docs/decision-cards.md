# Retired Decision Cards

The Bridge Decision Card was technically implemented and verified in [#127](https://github.com/menaje/codex-mcp-bridge-for-chatgpt/issues/127), with authoring and Codex permission checks in #131 and #132. It was retired by [#141](https://github.com/menaje/codex-mcp-bridge-for-chatgpt/issues/141) because its constrained card surface and runtime, security, and storage maintenance cost outweighed its product value. The separate user-effect study [#129](https://github.com/menaje/codex-mcp-bridge-for-chatgpt/issues/129) was not conducted; no effectiveness conclusion is implied.

`codex_decision`, `codex_decision_result`, `codex_ui_decision`, and the Decision v1 resource are no longer registered. Existing cached cards cannot create, revise, submit, redeliver, or retrieve results. Refresh the ChatGPT connector and reopen the current Dashboard or Settings cards. For complex choices, use the [standalone HTML workflow](standalone-decision-html.md) and explicitly return the chosen summary to the conversation. Codex questions still require a fresh input lookup and exact current `questionRef` before `codex_answer`.

Schema 24 migration and provenance remain immutable so older databases can upgrade. Schema 27 then drops its four legacy Decision tables, including stored submissions. A fresh schema-27 database has no Decision tables. The former 30-day card cleanup no longer runs. The migration's protected source snapshot temporarily retains pre-upgrade data for recovery; [the state upgrade runbook](state-upgrade-recovery.md#retired-decision-data-and-backup-disposal) explains when and how to dispose of it. This cleanup does not change Codex question delivery or `codex_answer`.

Historical implementation and security evidence remains in [the #127 audit](audits/2026-09-19-issue-127-decision-cards.md), [the CSS hardening audit](audits/2026-09-19-issue-127-css-hardening.md), [the #131 authoring audit](audits/2026-09-19-issue-131-decision-authoring.md), and [the #132 permission audit](audits/2026-09-19-issue-132-decision-codex-boundary.md). Those documents describe the feature as it existed at the time of testing, not the current tool surface.
