# GPT 질문 후속 검증

이슈: [#68](https://github.com/menaje/codex-mcp-bridge-for-chatgpt/issues/68)

최초 구현에서 남았던 서버형 일반 질문의 출처 문제를 해결했다. App Server
시작 시 `tool_call_mcp_elicitation`을 선택하고, 매 턴 전에 로드된 스레드의
기능 목록에서 `stable`·활성화 상태를 확인한다. 앱 승인은 MCP elicitation으로
분리되고 일반 네이티브 입력 요청은 GPT가 `codex_answer`로 답할 수 있다.
승인 결정·sandbox·저장된 접근 정책은 이 설정으로 변경되지 않는다.

조회 실패·미지원·비활성화, 다른 도구 항목과의 연결, 기존 앱 승인 ID는 일반
질문으로 분류하지 않는다. CLI 버전이나 동적 도구 이름만으로 추정하지 않는다.
구현 근거는 [공식 MCP 호출 소스](https://github.com/openai/codex/blob/main/codex-rs/core/src/mcp_tool_call.rs)와
설치된 CLI의 기능 목록·실제 서버 요청이다.

## 실제 CLI 결과

| CLI | 버전 | 서버형 질문 응답 | 앱 승인 분리 |
| --- | --- | --- | --- |
| 터미널 | 0.153.3 | `codex_answer` → 답변 반영 → 완료 | MCP elicitation, 공개 답변 거부 |
| 앱 내장 | 0.153.4 | 동일 | 동일 |
| 브리지 관리 | 0.153.4 | 동일 | 동일 |

서버형 질문 검사는 실제 `request_user_input` 발생을 필수 조건으로 두고
메시지형 응답으로 대체하지 않았다. 기본 모드 질문 도구 활성화는 격리된 임시
home에만 적용했다. 운영 브리지는 해당 실험 기능을 켜지 않는다.

승인 검사는 부작용 없는 전용 MCP 도구에 destructive annotation을 붙여 실제
승인 요청을 발생시켰다. 정확한 요청 참조로 공개 `codex_answer`를 호출했을 때
`not a current ordinary question` 이유로 거부된 것을 확인했다. 이후 승인 전용
경로에서 거절했고 세 CLI 모두 도구를 실행하지 않은 채 완료했다. 임시 인증
home은 모든 검사 후 제거했다. [원시 수치를 보존한 검증 JSON](2026-09-08-gpt-question-followup.json).

## 카드 호환성

호스트가 카드 호출의 대화 메타데이터를 생략하는 경우를 보완했다. 비공개 카드
정보에 대화 식별자를 포함하고, 카드 전용 도구가 질문 식별자·revision·토큰과
함께 검증한다. 호스트의 대화 정보가 있으면 그것을 우선하며, 다른 대화나 틀린
토큰은 거부한다. 공개 GPT 조회 도구에는 이 호환 입력을 추가하지 않았다.

## 실제 ChatGPT 검증

사용자가 플러그인을 **Refresh**한 뒤 기존 ChatGPT 대화를 인앱 브라우저에서
열어 검증했다. 실제 GPT가 새 질문 도구를 호출했고 새 대화는 필요하지 않았다.
이전 기록의 네이티브 앱 접근 거절은 브라우저 접근 제한을 뜻하지 않았다.
브라우저에서 처리할 수 있는 카드 조작을 사용자에게 요청했던 판단을 정정한다.
서버 도구 등록과 ChatGPT 메타데이터 갱신은 별개이며,
[공식 갱신 절차](https://developers.openai.com/plugins/deploy/connect-chatgpt#refresh-metadata)는
계속 적용된다.

| 실제 호스트 검사 | 결과 |
| --- | --- |
| 선택 카드 | `파랑` 선택 → 카드 새로고침 후 선택 유지 → 제출 → GPT 후속 실행·조회 → Codex 결과 확인 |
| 사전 공개하지 않은 자유 입력 | 카드 생성 후 한글 포함 임의 문자열을 카드에만 입력 → GPT 조회 → Codex 작업 생성 → 정확한 문자열 출력 |
| 완료 카드 재열기 | 전체 대화 새로고침 후 `GPT가 답변을 확인했습니다.` 유지, 입력란·제출 버튼 0개 |
| 취소 | 실제 카드에서 취소 → GPT 후속 실행 → `codex_user_answer`가 `cancelled` 반환 |
| 만료 | 실제 1분 경과 → 만료 안내, 제출 버튼 0개 → 새로고침 후 만료 레코드 정리 |

첫 선택 검사는 선택값을 GPT에 미리 알려줬고, 기록상 조회보다 Codex 작업
생성이 앞섰으므로 실제 답변을 읽고 전달했다는 인과 증거로 사용하지 않는다.
이를 확인하기 위해 별도의 자유 입력 검사에서는 카드 생성 후 검증 문자열을
만들어 카드에만 입력했다. GPT가 정확한 `responseRef`를 조회한 시각이 Codex
작업 생성보다 9,914ms 앞섰고, Codex 완료 결과는 저장된 답변과 정확히 같았다.
표준 카드 후속 메시지가 실제 GPT를 재개했으며, 수동 후속 프롬프트로 제출을
대체하지 않았다. 카드의 사용자 조작은 사용자가 위임한 인앱 브라우저로 수행했다.

카드 검증에서 실행한 두 Codex 작업의 공개 이벤트는 메시지·턴·사용량뿐이었다. 취소·만료 전후
작업 수는 2개로 동일했다. 실제 호스트의 거절·미지원·전달 중 연결 오류를
강제로 발생시킨 검사는 수행하지 않았다. 해당 실패 경로는 아래의 모의 호스트
회귀 검사로 확인했으며 실제 호스트의 검증 결과로 확대하지 않는다. 닫힌 대화나
해제된 카드에서도 GPT가 항상 자동 재개된다는 보장은 하지 않는다.

원시 검증 기록은 무시되는 `output/question-host-acceptance/live-chatgpt-blind.json`과
`live-chatgpt-lifecycle.json`에 보관했다. 공개 JSON에는 대화·작업 식별자와 원문
검증값을 제외한 결과를 기록한다.

### GPT가 직접 답하는 일반 질문

별도 Activity와 새 Agent에서 Codex의 최초 지시에는 Blue·Red 선택지만 넣고
선택할 답은 상위 GPT에만 알려줬다. 실제 ChatGPT 도구 검사창에서 최초 지시,
`codex_input` 응답과 최종 `codex_steer` 전달 확인을 읽었다.

- `gpt-6-astra / low`: 실행 중인 정확한 Job의 일반 메시지 질문을 GPT가 읽었다.
  구조화된 질문·승인은 0개였고, GPT가 `codex_steer`로 Red를 전달했다. 같은
  Codex 턴의 최종 출력은 `GPT_DIRECT:Red`였다. 사용자 질문 카드 생성은 0개였다.
- 실제 호스트 기록에는 steer 호출 4개가 있었다. 앞선 3개는 검사창에서 도구
  응답이 표시되지 않았고, 상태·입력 재조회 후 Job version 8을 사용한 마지막
  호출에서 `delivery.status=delivered`를 확인했다. 응답 미표시만으로 앞선
  호출의 전달 여부나 정확한 오류 원인을 추정하지 않는다.
- 앞선 `gpt-5.6-luna / low` 실행은 질문 뒤 대기를 사용하지 못하고
  `PROBE_UNAVAILABLE`로 종료했다. GPT는 종료된 Job에 대한 전달이 거부됐다고
  보고했고 이를 직접 응답 성공으로 기록하지 않았다. 이 실행 결과를 모든
  모델 설정에서의 영구적인 미지원으로 일반화하지 않는다.

카드 검사와 두 직접 응답 검사의 Activity 3개는 모두 완료 상태로 정리했다.
Codex 턴은 총 4개가 종료됐으며 파일·명령·외부 도구 작업은 없었다. 원시 기록은
`output/question-host-acceptance/live-chatgpt-direct.json`과
`live-chatgpt-direct-unavailable.json`에 보관했다. 이 검사는 명시된 위임과
질문 시나리오에서의 실제 도구 동작을 확인하며, 모든 상황에서 GPT가 질문
필요성을 올바르게 판단한다는 보장은 하지 않는다.

## 검증 및 로컬 서비스 반영

- TypeScript 빌드, 릴리즈 계약, 출력 계약 감사, CLI App Server 계약 통과.
- 최종 전체 실행에서 61개 파일의 747개 테스트 통과. 추가된 비공개 카드
  `scopeId`에 대한 도구 목록 스냅샷 1개를 갱신하고 해당 테스트 통과를 별도
  확인했다. 총 748개 테스트의 검증 결과이며 `output/**`의 이전 빌드 복사본은 제외했다.
- 빌드된 카드의 실제 Chromium 검사 6개 통과: 표준·호환 후속 메시지,
  대화 메타데이터 누락, 거절 후 재시도, 전달 불확실, 만료. 직접 Codex 호출 0회.
  화면 이미지도 확인했다. 이 검사의 ChatGPT 호스트는 모의 구현이다.
- macOS 빌드·서명 검사와 100개 테스트 실행 통과(2개 건너뜀), 9개 언어 검사 통과.
- 전역 활성 작업·대기 승인·메모리에만 남은 작업·백그라운드 프로세스가 모두
  0임을 확인하고 drain으로 서비스를 종료했다. 기존 앱과 schema 12 데이터의
  일관된 SQLite 백업을 보존한 뒤 새 앱으로 교체했다.
- 현재 로컬 서비스 빌드: `54296e0f0010-dirty:9af435da30f3`. SQLite schema 13,
  무결성 검사, helper·bridge 연결, 보안 터널 재연결, 새 질문 도구 7개 노출 확인.
  기존 등록 프로젝트·접근 정책은 유지했다. 공개 릴리즈는 발행하지 않았다.

로컬 교체 영수증은 무시되는 `output/question-host-acceptance/install-receipt.json`에
있으며, 이전 앱과 데이터 백업 위치를 포함한다. 이전 실행 파일로 되돌릴 때는
schema 13 이후 새 데이터의 보존 여부를 검토해야 하며 이전 DB를 무조건 덮어쓰지 않는다.
