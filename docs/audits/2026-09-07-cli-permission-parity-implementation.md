# Codex CLI 권한·기능 일관성 수정 결과 · 2026-09-07

[선행 감사](2026-09-07-cli-permission-parity.md)에서 발견한 A1–A7의 브리지 공통 경로를 수정했다. 터미널 CLI, 앱 내장 CLI, 브리지 관리 CLI 모두 같은 권한 결정·실행 정책 확인·기능 검사 경로를 사용한다. 이 문서는 로컬 작업 트리의 구현과 검증 결과다. 운영 브리지를 배포하거나 재시작하지 않았으며, 저장된 접근 전략·승인 정책·선택 CLI도 변경하지 않았다.

## 변경한 동작

| 감사 항목 | 적용한 수정 | 회귀 검증 |
| --- | --- | --- |
| A1: 기존 세션이 현재 운영자 권한 상한을 우회 | 새 작업·이어가기·분기에서 같은 정책 결정 함수를 사용하고 기존 세션 권한도 현재 상한으로 검사 | 전체 접근 허용을 끈 후 기존 세션의 이어가기·분기가 작업 등록과 upstream 호출 전에 거절됨 |
| A2: 분기에 명시한 sandbox 무시 | 분기 요청의 sandbox를 끝까지 전달하고 기존 세션과의 충돌을 검사 | 공개 v2 요청을 포함해 명시적 제한이 조용히 사라지지 않음 |
| A3: App Server의 적용 정책 확인 누락 | start/resume/fork 응답의 sandbox 모드·승인 정책·작업 폴더를 요청과 비교하고 승인 담당자·프로필·세부 정책을 보존하여 turn에 전달 | 세 메서드 각각의 모드·승인·폴더 불일치 및 증거 누락 12건에서 추가 turn/start가 전송되지 않음 |
| A4: 이어가기의 비대칭 권한 충돌 처리 | 기존 세션과 다른 sandbox는 변경 방향에 관계없이 거절하고 새 문맥을 안내 | 읽기 전용→쓰기와 쓰기→읽기 전용에 같은 규칙 적용 |
| A5: 버전만으로 호환성 판정·고정 기능 플래그 | 설치 CLI가 생성한 요청 스키마로 브리지에 필요한 메서드·필드·입력 조합을 검사하고 기능 지원 여부를 계산 | 필수 계약 미지원 시 작업·Activity·Agent 등록 전 거절, 선택 기능 누락은 해당 기능에 반영, 같은 버전의 worker 교체도 재검사 |
| A6: MCP 추가 입력·비차단 질문 중계 공백 | 표준 MCP form/URL 요청과 isBlocking/isOther를 어댑터·응답 도구·Activity 카드에 전달 | 입력 형식·선택지·응답 일회성·비공개 데이터 경계 및 브라우저 제출 흐름 검증 |
| A7: 고정 모드의 동일 sandbox도 거절 | 저장된 고정 정책과 같은 명시적 값은 허용하고 다른 값은 요청값·저장값을 포함한 충돌로 반환 | 동일 정책 성공, 상충 정책은 실행 전 거절, 제한 필드를 무조건 삭제하라는 안내 제거 |

고정 전체 접근에서 `read-only`를 명시하면 `SANDBOX_CONFLICT`가 발생한다. 사용자의 제한을 제거해 다시 실행하도록 유도하지 않는다. sandbox를 생략하면 저장된 고정 정책이 적용된다는 점도 오류에 명시한다. 이어가기·분기는 기존 sandbox를 유지하며 다른 권한이 필요하면 새 문맥을 사용한다.

접근 전략은 파일 접근 범위를 결정한다. `always-full`을 선택했다고 명령 승인 정책을 `never`로 변경하지 않는다. 실행 결과에는 확인된 sandbox·승인 정책·승인 담당자·프로필과 네트워크/임시 폴더 설정·쓰기 루트 개수만 남기며, 세부 경로는 공개하지 않는다.

권한 확인의 범위는 브리지가 요청한 sandbox 모드·승인 정책·작업 폴더의 일치와 현재 App Server가 확인한 세부 정책의 전달이다. 지정된 프로필은 단순 sandbox 값으로 재구성하지 않고 프로필 식별자를 보존한다. worker를 새로 시작해 세션을 불러올 때도 현재 요청과 응답을 다시 확인한다. 과거 프로필의 모든 세부 쓰기 경로가 재시작 후 바이트 단위로 같다는 보장은 추가하지 않았다.

## CLI 호환성과 상호작용

CLI 파일의 존재·무결성과 실행 계약의 호환성을 구분했다. 새 필수 입력처럼 실행을 깨뜨리는 변경은 감지하고, 부가 필드가 늘어나는 변경이나 새 버전 문자열은 일률적으로 차단하지 않는다. 실행 계약을 확인하지 못한 상태에서 선택 기능을 지원한다고 광고하지 않는다. 명시적으로 고른 CLI가 호환되지 않으면 다른 설치본으로 조용히 대체하지 않는다.

worker를 시작하거나 교체할 때 현재 실행 파일의 계약을 확인한다. 같은 경로·같은 버전으로 파일이 교체된 경우도 이전 판정을 재사용하지 않는다. 응답하지 않는 스키마 생성기는 제한 시간 뒤 검사기가 만든 프로세스 그룹을 종료하고 임시 디렉터리를 정리한다.

MCP form은 평면 문자열·숫자·정수·불리언·문자열 배열과 표준 선택지를 처리한다. URL 요청은 사용자가 링크를 열고 별도로 완료·거절·취소할 수 있다. 확장 openai-form은 활성화하지 않았으며, 지원하지 않는 형식은 명시적으로 취소한다. 모든 MCP 확장 형식을 지원한다는 뜻은 아니다.

원본 URL·폼 스키마는 대기 중인 upstream 메모리와 해당 카드의 비공개 입력 메타데이터에만 전달한다. 공개 이벤트·작업 저장소에 복사하지 않는다. 답변은 현재 작업·카드·interaction 검사를 거쳐 원래 요청에 전달하며 원문을 저장하지 않는다. 비차단 질문은 작업을 대기 상태로 바꾸지 않고, `isOther: false`인 선택 질문에는 임의 답변란을 표시하지 않는다.

## 검증 범위와 운영 반영 상태

실제 CLI 검사는 격리된 Codex home과 임시 파일만 사용했다. 모델 turn이나 인증된 계정별 도구 호출을 실행하지 않았다. 계속하기·분기·worker 재시작·정책 불일치·MCP 입력의 어댑터 회귀 검증은 합성 JSON-RPC peer를 사용했다. 빈 스레드의 `no rollout found` 응답을 실제 지속 세션 재개 성공으로 계산하지 않았다.

따라서 이번 통과 결과는 로그인한 모델의 전체 작업, 실제 외부 앱의 인증 링크, 네트워크 허용/차단, 모든 세부 권한 프로필, 다른 OS 또는 ChatGPT Web/Desktop/iOS 전체를 검증했다는 의미가 아니다. 설치본·계정·호스트의 차이는 명시적으로 표시하고 지원되는 공통 입력의 권한 의미를 일관되게 유지하는 것이 구현한 기준이다.

수정은 소스·테스트·문서·로컬 빌드까지 완료했다. 실행 중 브리지의 배포·재시작과 운영 환경의 인증된 후속 확인은 수행하지 않았다. 같은 작업 트리에서 진행 중이던 별도 변경은 보존했다.
