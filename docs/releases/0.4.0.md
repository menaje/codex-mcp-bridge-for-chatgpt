# Codex MCP Bridge for ChatGPT 0.4.0

This release adds the native macOS menu-bar application and brings task execution,
status, user questions, recovery, and release validation under one product contract.
The generic npm server remains available for users who run the bridge directly.

## Highlights

- Run Codex through the selected CLI's App Server, with centralized authentication,
  installation, updates, model and reasoning policy, permissions, and task recovery.
- Use the native macOS menu-bar app on Apple Silicon or Intel Macs. It manages the
  helper, bridge, Tunnel connection, setup, diagnostics, status, settings, remote
  connections, notifications, and safe shutdown.
- View current and completed work in the Dashboard, answer separate user questions,
  inspect failures, and use scoped stop and recovery controls. Settings, Dashboard,
  and Question are the active cards. New work no longer opens an Activity card.
- Share one language preference across the app and cards, with English, Korean,
  Japanese, Simplified and Traditional Chinese, Spanish, French, German, and
  Portuguese support.
- Preserve supported cached cards through a release catalog. The exact v0.3.0
  Settings and Activity resources and the explicitly deployed development card set
  remain available with their original metadata, presenters, and required tools.
  Intermediate development snapshots are excluded from release packages.
- Upgrade supported SQLite schemas 3 through 18 to schema 19 with one verified
  source snapshot, migration provenance, integrity and foreign-key checks, restart
  recovery, and an explicit pre-service restore boundary.

## Migration and compatibility

Stable installations continue to use `~/.codex-mcp-bridge/state.sqlite`. Candidate
and development builds use separate `candidate` and `development` profile databases
by default. Stop every bridge owner before deliberately selecting the stable profile
or an absolute operational database for an upgrade. Keep the generated backup and
its sidecar until the candidate, restart, recovery rehearsal, and your rollback
window are complete.

Fresh installations create schema 19. Existing schema 3 through 18 databases migrate
automatically after preflight. Schemas 1 and 2 and the retired standalone Settings,
session, and Job JSON stores are no longer accepted or imported. Follow the
[state upgrade and recovery runbook](https://github.com/menaje/codex-mcp-bridge-for-chatgpt/blob/release/0.4.0/docs/state-upgrade-recovery.md) before changing a
state profile or restoring a backup.

The internal MCP and Codex SDK execution backends have been removed. Historical
records remain readable, but work from a retired backend does not silently resume
under another account or storage location. Start a fresh context and provide an
explicit handoff summary when continuity is needed.

Task calls no longer accept GPT-supplied filesystem permission fields. The bridge
applies the access policy saved in Settings. Project selection uses registered named
projects, and current model and reasoning choices must satisfy the selected CLI's
catalog. Refresh the ChatGPT connection after installation so new conversations use
the current tool and card contracts.

Agent archive and restore operations have been removed. Migrated archived Agents are
restored as retained history without replaying their work. Activities, Agents, Jobs,
questions, answers, results, cancellation and idempotency state remain preserved.

Legacy Activity cards stay compatibility-only through the documented support window:
at least 60 days and two later stable releases after 0.4.0, whichever is later.
Dashboard and Question replace Activity for new presentations. This release does not
delete the shared execution or history data behind those cards.

## macOS downloads

Choose the DMG that matches the Mac:

- `macOS-arm64-unnotarized.dmg` for Apple Silicon
- `macOS-x64-unnotarized.dmg` for Intel

Both applications are ad-hoc signed and are not Apple-notarized. If macOS blocks the
first launch, approve only **Codex MCP Bridge for ChatGPT** in **System Settings →
Privacy & Security**, then open it again. Do not disable Gatekeeper globally.

Node.js 22 or later, an authenticated supported Codex CLI, and `tunnel-client` remain
external prerequisites. The release also contains the generic npm archive, its
SHA-256 file, and `SHA256SUMS.txt` for all downloadable assets.
